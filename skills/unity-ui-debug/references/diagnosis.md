# 按症状选择的诊断分支

只读与当前故障相关的部分。检查项用于产生可证伪假设，不是必须执行的清单；业务状态、框架创建/缓存机制和资源覆盖关系以当前项目为准。

## 布局：在哪一层首次偏离

先比较同一对象、同一状态、同一尺寸的预期与实际。Prefab 编辑器和 Game View 的父级环境可能不同，不能直接按截图差异认定序列化错误。

| 证据方向 | UGUI 中可观察内容 | UI Toolkit 中可观察内容 |
|---|---|---|
| 父级尺寸/坐标系 | 实际 Canvas、父 RectTransform、锚点、轴心、局部与世界坐标 | 挂载的 Panel、父元素大小、resolvedStyle、坐标转换 |
| 自动布局覆盖 | LayoutGroup、ContentSizeFitter、Animator、运行时赋值 | flex、USS 优先级、内联 style、绑定或脚本更新 |
| 生成结果差异 | 若存在生成器，对比源、导出数据与实例 | 若存在生成器，对比源、UXML/USS 与实际元素树 |

缩放正确不代表控件会随宽高比调整；先确认项目期待缩放、拉伸、锚定、裁剪还是保持比例。不要把某个项目的参考分辨率当作默认值。

## 属性：谁最后写入

当 Inspector 修改无效，选一个具体属性追踪：编辑资产 → 实例化或加载 → 初始绑定 → 状态切换 → 每帧更新 → 保存/再生成。

对比设计值和运行值，并查找直接赋值、动画轨道、样式/主题、绑定器及父级影响。实例上的值与 Prefab 的值不同可能是设计行为；先确认哪些值应由用户控制，哪些值是业务派生状态。

透明度要区分自身颜色、父级透明度、材质、主题和状态变化。点击透明区域的行为与显示透明度也不一定相同，不要用改变视觉透明度代替输入规则。

## 输入：在哪一步被拦截

把事件收到、命中对象、可交互状态、手势识别和业务处理结果分开观察。

- UGUI：针对实际对象检查 EventSystem/输入模块、Raycast 命中、CanvasGroup、透明遮罩、按钮状态和监听。
- UI Toolkit：检查实际命中元素、pickingMode、事件传播、焦点、pointer capture 和绑定回调。
- 拖动“不流畅”：区分启动延迟、坐标跳变、视觉跟随滞后。对比 pointer down、阈值达成、begin drag 的时点；不要默认是性能或插值问题。

## 生命周期：首次正常为何重开失败

比较首次与再次打开时的实例身份、激活状态、缓存引用、订阅数量、输入锁以及异步请求归属。

隐藏对象可能继续持有数据/锁；关闭界面时发出的异步操作可能在新实例或新状态出现后返回。依据框架真实创建和激活顺序判断引用何时可用，不假设跨组件 Awake 的顺序，也不以无条件延迟一帧作为通用修复。

观测应尽量带对象身份和状态转换原因，以区分“没有刷新”“刷新后被覆盖”和“旧回调修改了新状态”。不要仅凭方法名字认为它会执行完整初始化或清理。
