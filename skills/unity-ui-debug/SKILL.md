# Unity UI 排障

此技能补充容易漏查的 UI 证据，不代替对项目业务、资源和框架的理解。不要按固定顺序穷举所有组件，也不要预设 Canvas、转换器或生命周期就是根因。

## 先建立最小上下文

- 读取适用的项目规范、相关模块入口及当前 Git 改动；沿出问题的对象和操作追踪调用链，不默认扫描全项目或创建知识图谱。
- 区分用户已观察到的事实、用户对根因的推测和自己的假设。只澄清影响复现、行为或修复范围的缺项；不因缺少所有截图、设备或日志而停止已有分析。
- 确认实际使用 UGUI、UI Toolkit 或其他实现，Prefab/场景/生成源的编辑归属。存在生成工具时才检查生成链；保留当前人工调整。
- 用户只要求分析时保持只读；已要求修复时，在证据足够后继续，不为每个内部步骤重复确认。

## 选择能区分原因的观察

仅在相应现象出现时读取 [诊断分支](references/diagnosis.md)，选择一条与项目证据匹配的路径：

- **布局不同**：找出源布局、生成数据、序列化资产、实际实例和运行时布局中最早出现差异的位置。
- **手调无效**：确认编辑的是哪个实例/资源，追踪该属性的写入者、写入时点及保存入口。不要先删除所有运行时赋值。
- **输入异常**：区分未收到输入、被遮挡、被状态禁止、阈值/延迟和事件处理后又被覆盖。
- **重开或返回后异常**：比较首次与复用实例的状态、引用和异步回调，不假设隐藏等于销毁。

先记录一个假设及能推翻它的观察，再选择局部日志、断点、运行时属性或最小场景对照。复杂问题可以跨分支追踪，不要求机械完成表格。静态代码只能支持推断时明确说出证据强度；临时恢复正常不足以确认根因。

## 修复与结束

修改最早违反项目约定的环节，不用逐页位移补丁掩盖通用布局错误，也不为局部故障重构整个框架。临时观测不要逐帧刷屏；结束时移除仅本次需要的诊断代码，保留用户要求的调试入口。

回归原复现条件及最相关对照：布局问题测约定分辨率；复用问题测关闭重开/场景往返；输入问题测相应点击与拖动路径。不要顺带跑所有设备和无关测试。编译通过不能证明视觉或交互已通过。

简要交付故障机制与证据、修改位置、已验证和未验证项；涉及配置时说明哪里调整、是否会被运行时代码覆盖。只更新受影响的项目文档；不要把一次故障的推断写成全局规则。得到足以支持修复的证据且相关验证完成后结束排查。
