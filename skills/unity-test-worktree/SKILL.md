# Unity 测试工作树

目标是验证本次交付的内容，同时保留开发工作区和其他任务的工作。项目的测试入口、版本和隔离策略优先；本技能不硬编码分支、路径、测试框架，不要求每次新建工作树。

## 确定待测对象

读取适用规范、Git 状态、已有测试说明及 Unity ProjectVersion。明确测试的是某个提交还是当前工作区（含未提交代码、资源和 .meta）；未指定时，以本次交付内容为待测对象。

优先复用项目现有同步、占用与测试脚本；使用前理解其输入及清理范围。只运行静态检查时无需建立 Unity 环境。不要把主编辑器打开视为停止全部工作的理由。

## 验证流程

实际同步或启动 Unity 前读取 [隔离验证操作](references/verification.md)。关键约束如下：

1. 确认开发根、测试根、Git 工作树身份、Unity 子目录和编辑器版本。路径不同不等于独立工作树；测试树必须与开发树是同一仓库的不同 worktree。
2. 确认没有其他任务使用目标。优先采用项目已有互斥机制；没有机制时检查实际 Unity 命令行和协作者状态，检查结果只是一时快照，不是已取得锁。
3. 对齐基线，再同步已明确的未提交/未跟踪内容及删除项。同步前发现不明改动或分叉时先调查，不自动 reset、clean、rebase 或覆盖。同步后允许符合待测清单的 dirty。
4. 使用项目校验工具，或只读运行 `scripts/inspect_worktrees.py --source <开发根> --target <测试根>`。它比较 Git 可见文件字节与路径，检查工作树关系；不是同步工具、Unity 占用检测或完整环境证明。忽略文件、外部依赖和子模块另行核对。
5. 运行与变更相关的验证，并把运行前后的内容核对结果关联到测试日志。内容在验证中改变时，判断受影响范围；不能沿用旧结果宣称新改动通过。
6. 分别判断测试结果、退出码和进程状态。测试结果已写出但进程未退出时，只能处理已确认属于本次启动的进程，不能按名称杀掉所有 Unity。

被占用时继续能独立完成的工作；按已有授权等待并报告真正的阻塞。不要为绕过占用无限创建临时 Unity 项目。任务完成后仅回收本次明确创建的临时资源；专用测试树及其缓存可以保留，不要求清空。

## 报告边界

交付说明源提交及未提交内容标识、测试位置、执行项/结果、未运行项以及占用或收尾状态。文件比对成功仅说明该次 Git 可见快照一致，不能证明 Unity 版本、包缓存、忽略资源或测试本身正确。

复用本次既有授权，不额外制造确认环节。发现可能覆盖其他任务内容或需要改变测试范围时说明具体冲突；等待期间继续独立验证。只更新受本次影响的项目文档。
