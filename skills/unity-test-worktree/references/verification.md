# 隔离验证操作

## 定位与占用

用 `git worktree list --porcelain` 和各路径的 `git rev-parse --show-toplevel` 核对身份。读取 Unity 子目录的 ProjectSettings/ProjectVersion.txt；编辑器位置由项目说明或当前机器环境发现，不在通用技能中固定某个盘符。

检查 Unity 进程的完整命令行与目标 projectPath，同时确认其他 Agent/终端任务没有占用该测试树。仅检查文件锁或只检查进程名都不足够。项目有调度器或锁时沿用；本技能的只读脚本不取得锁，也不保证后续没有竞争。无法确认时不要对共享测试树开始写入。

## 同步范围

- 只有干净、无独立任务改动、确认为落后且未分叉的专用测试分支，才可在已有授权下快进到待测基线。
- 对当前工作区测试，另外同步未提交和必要未跟踪文件、资源与 .meta、删除项。暂存区不等于某个 Agent 的独立所有权，不以是否暂存判断谁拥有文件。
- 项目已有安全同步脚本时优先使用。缺少脚本时先列出操作清单，采用路径明确的复制和逐项处理；不要临时拼装整个目录的镜像删除命令。
- 忽略文件不是天然无关：本地包、生成代码、资源、构建配置可能影响结果。核对必要项，但不把 Library、Temp、Logs 等缓存盲目复制到另一棵树。
- 需要删除或回滚的内容必须能够确认属于本次同步，且目标解析后仍在明确测试根内。不要直接调用整树 `git clean`、`git reset --hard` 或 `git restore .`。已有专用清理脚本也应在同一执行过程中绑定路径、仓库身份、占用及删除范围检查。

## 只读内容核对

需要 Python 3.10+ 和 Git；脚本无第三方依赖。可从技能目录运行：

```text
python -X utf8 scripts/inspect_worktrees.py --source "开发仓库根"
python -X utf8 scripts/inspect_worktrees.py --source "开发仓库根" --target "测试仓库根"
```

输出 JSON；通过重定向保存到项目指定的日志/临时目录。不要把报告保存到参与本次比对的非忽略目录，否则报告自身会成为差异。

- `0`：单树成功生成 Git 可见快照，或两个不同 worktree 的可见内容相同。
- `1`：同仓库不同工作树内容存在差异。
- `2`：路径/仓库身份错误、扫描期间检测到变化、子模块/符号链接等无法证明的情况，或 Git/文件读取失败。

完整比较全部 Git 已跟踪文件与非忽略的未跟踪文件，采用 SHA-256，不输出文件正文。包含 .meta；Git 已跟踪但被 .gitignore 匹配的文件仍会比较。确认删除的文件不计入当前内容；目标还保留该文件会报告差异。Git 模式差异不等于字节差异，脚本不验证可执行位或 ACL。

对符号链接、目录联接和子模块拒绝给出一致证明，不沿链接读取外部内容。采用严格字节比较，因此仅行尾不同也会报告差异。Unity 项目中无关文档也可能形成差异；可解释并记录它们，但不要把非零结果改称全树相同。

单树模式可用于记录运行前后摘要。一次扫描不构成原子文件系统快照；脚本能检测部分并发变化，不能替代独占使用和执行前后核对。它不检测 Unity、忽略文件内容、外部依赖、LFS 本地文件是否完成下载或缓存状态；不要把退出码 0 当作可以启动测试的唯一条件。

## 执行与收尾

使用项目已验证的 Unity 命令/测试入口，按类型选择编译、EditMode、PlayMode、资源导入或最小场景。记录运行开始时的内容摘要、日志路径及新启动进程身份。

区分：未启动、执行失败、测试失败、测试通过、无法判定。结果文件存在不代表本次测试成功，要核对时间、本次选择的测试和结果内容。进程退出码与测试框架结果互相核对。

测试进行中收到新的代码改动时，重新比对待测范围；旧结果可以说明旧快照的状态，不能证明新快照。测试结束后没有必要重复全套验证，除非新改动、失败或剩余风险要求这样做。

关闭本次启动的测试进程、处理本次临时资源即可；保留专用测试树。临时 Unity 项目确需删除时，在同一操作过程中校验绝对路径与归属，不把计算出来的未检查路径交给另一个 shell 删除。
