# Unity 项目检查

## 必查事实

1. 找到仓库根与 Unity 项目根；两者可能不是同一目录。
2. 读取从仓库根到目标文件路径上所有适用的 `AGENTS.md`。
3. 检查 Git 分支、未提交文件、未跟踪资源和并发修改。
4. 确认 Unity 版本、渲染管线、关键 Packages 和第三方依赖。
5. 检查 `.codegraph/`、程序集定义、测试目录及项目文档入口。
6. 确认场景、Prefab、ScriptableObject、资源 GUID 和 `.meta` 的关系。

## 理解代码时的最小范围

- 目标脚本。
- 上游调用入口。
- 下游依赖。
- 数据与配置定义。
- 运行时状态拥有者。
- 表现或 UI 订阅者。
- 序列化、存档或网络边界。
- 相邻测试。

## 需要警惕

- 同一个数据被逻辑层和表现层同时修改。
- 动画完成回调重复结算玩法状态。
- 对象池回收中途抛异常，留下激活对象。
- 不同对象的 `Awake` 顺序被当作确定顺序。
- 外部资源被自动搜索，导致场景或 Prefab 隐式依赖。
- 为规避空引用而吞掉配置错误。
- 修改共享材质、共享 Mesh 或共享 ScriptableObject 导致全局副作用。
- 直接编辑 Prefab/场景 YAML 时破坏 GUID 或序列化字段。

## 可接受的检查输出

在开始实现前形成短摘要：

```text
仓库根：
Unity 项目根：
适用约束：
现有模块入口：
状态所有者：
外部依赖：
用户已有改动：
验证入口：
```
