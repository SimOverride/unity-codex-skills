# 文档路由

## 设计文档

记录模块解决的问题、功能、行为规则、状态规则、职责边界与非目标。原则上不出现类名、接口名、方法名、字段名、脚本路径、Prefab 层级和生命周期实现。

## 开发文档

记录当前代码结构、核心数据、依赖、调用流程、初始化顺序、事件流、资源组织、测试入口和已知技术限制。

## 使用说明

记录场景与 Inspector 配置、操作步骤、验证方法、常见错误、排查顺序和人工验收。

## 总体文档

只在模块改变项目能力、跨模块关系、主流程或外部依赖时更新。不要复制模块细节。

## CHANGELOG

记录对使用者或协作者有影响的新增、变化、修复、删除和迁移要求。不记录排查过程、被否决方案和普通重构细节。

## AGENTS.md

只记录未来开发仍必须遵守的约束性决定。例如状态唯一所有者、特殊类型互斥、命名约定或固定事件顺序。临时实现细节和单次任务过程不进入该文件。

## 当前状态原则

- 需求改变后直接替换旧描述。
- 不写“以前如何、后来改成如何”。
- 历史由 Git 和 CHANGELOG 承担。
- 文档内容必须与当前代码、资源和配置一致。
