# UI 排障与隔离测试

## UI 排障

### 设计

帮助开发者选择与实际问题有关的证据，减少把显示、输入、业务状态和编辑来源混为一谈的情况。不承诺通用流程可以自动定位复杂项目的根因，不固定排查顺序，不替代对调用链和资源的理解。

适用于已有界面异常；新页面制作和明确的材质问题由相应工作流处理。分析与修复边界由用户当前授权决定，人工编辑资产不能因排障而被重新生成覆盖。

### 开发

入口为 `skills/unity-ui-debug/SKILL.md`，`references/diagnosis.md` 按布局、属性覆盖、输入和生命周期提供条件分支。`agents/openai.yaml` 提供中文展示与调用提示，沿用默认自动发现模式。

没有添加自动改 Prefab 或扫描整个项目的脚本；UGUI/UI Toolkit 检查点只提供观察方向，项目实际实现优先。与 `unity-render-debug` 按故障证据区分，避免为一次 UI 问题同时运行全部渲染检查。

### 使用说明

显式调用示例：

```text
使用 $unity-ui-debug 排查返回主界面后按钮不能点击的问题。
我已手动调整 Prefab，先分析，不要重新生成。
```

最好提供触发步骤、预期、实际以及最近修改；现有项目能够确定的信息无需再次填写。输出应区分直接观察和静态推断。纯代码检查通过后，视觉和交互仍未验证时必须说明。

## 隔离测试

### 设计

验证当前交付内容，同时保护开发工作区和其他任务。优先复用现有测试环境；内容同步与测试占用分别确认，不把路径差异、工作区干净或测试结果文件存在当作充分证明。

允许测试环境包含已知待测改动。所有清理与进程回收都限于本次可确认归属，不要求测试完清空环境。

### 开发

入口为 `skills/unity-test-worktree/SKILL.md`，具体流程在 `references/verification.md`。只读脚本 `scripts/inspect_worktrees.py` 依赖 Python 3.10+ 和 Git，支持单树快照及同仓库双树比对。

脚本读取 Git 身份、HEAD、状态与文件清单；对 Git 可见普通文件计算 SHA-256，包含未提交、未跟踪且非忽略文件及元数据。拒绝相同目录、独立克隆、冲突、子模块、符号链接/重解析点和检测到的并发变化。严格比较文件字节，不验证文件模式、忽略资源、Unity 进程、包缓存或 LFS 下载状态。

脚本没有创建、同步、删除、重置或启动 Unity 的命令。这样只把容易误判的内容核对机械化，环境写入仍由项目专用流程处理。

### 使用说明

```text
使用 $unity-test-worktree 验证本次改动。
复用项目规定的测试树，包含当前未提交资源，运行受影响的测试。
```

只读脚本从任意目录运行，传绝对仓库根：

```text
python -X utf8 <技能目录>/scripts/inspect_worktrees.py --source <开发根> --target <测试根>
```

退出码 0 表示可见内容一致（单树模式表示生成快照成功），1 表示差异，2 表示无法可靠比对。报告为 JSON，不包含文件正文。不要把报告输出到参与扫描的非忽略目录。

差异先核对同步清单，尤其是未提交资源、.meta、删除项和行尾；占用先核对任务与 Unity projectPath；子模块/链接/忽略资源采用项目对应验证，不跳过后宣称全环境一致。

## 验证与限制

结构验证使用 skill-creator 的 `quick_validate.py`。脚本回归入口：

```text
python -X utf8 -m unittest discover -s tests -v
```

测试使用真实临时 Git 工作树，覆盖一致内容、预期 dirty、修改/删除/新增元数据、忽略文件、暂存区与工作区差异、行尾、同路径/独立克隆拒绝、子模块/链接拒绝、并发状态变化和 CLI 退出码。临时目录限定在仓库忽略的 `work/tests`，结束后清理，不创建 Unity 项目。

这些检查只证明格式与辅助脚本的相应行为，不证明 Agent 在复杂项目中的诊断质量。真实 Unity 编辑器占用、测试启动与 UI 行为仍需后续真实任务前向验证；不得用脚本回归代替该结论。
