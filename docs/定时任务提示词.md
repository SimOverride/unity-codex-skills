# 定时任务提示词

## 月末只读复盘

推荐时间：每月最后一天 20:00。

```text
复盘过去一个完整自然月的 Codex 任务。

读取任务标题、用户请求、重要澄清、最终结果、交付文件、验证结果、回退和返工记录。不能只依据标题或自动摘要。

按项目、领域、工作类型、输入、输出、使用的 Skill、完成状态和返工原因分类。

识别跨任务重复出现的工作流。候选工作流必须至少有两个不同真实案例，并且输入、步骤、输出与验收相对稳定。

对每个候选按 1 至 5 分评估：
- 频率
- 稳定性
- 出错成本
- 可沉淀资源
- 独立性

输出：
1. 本月工作主线与成果。
2. 已有 Skill 的使用与命中情况。
3. 重复工作流及案例证据。
4. 失败、返工和用户纠正。
5. 建议新建 Skill。
6. 建议更新 Skill。
7. 继续观察。
8. 不适合 Skill 的内容及其正确去向。
9. 下月验证计划。

将报告保存到当前 Skill 仓库的 docs/reviews/YYYY-MM.md。

本任务只读分析。不得修改 Skill、AGENTS.md、项目代码、任务记录或外部仓库，不得提交或推送。
报告不得包含凭据、完整私有代码、敏感业务数据或无必要的本地绝对路径。
```

## 月初更新评估

推荐时间：每月第一天 10:00。

```text
读取 Skill 仓库中最新的 docs/reviews/YYYY-MM.md，并核对报告引用的原始任务案例。

对每项建议判断：
- 是否至少有两个不同真实案例。
- 是否属于跨项目可复用流程。
- 是否已经被现有 Skill 覆盖。
- 是否应该写入项目 AGENTS.md。
- 是否更适合确定性脚本。
- 是否拥有清晰的触发和非触发条件。

输出一份更新提案，包含：
1. 目标 Skill 或拟创建名称。
2. 案例证据。
3. 当前缺陷。
4. 拟修改的 SKILL.md、references、scripts。
5. 验证方式。
6. 风险和不修改的内容。

默认只输出提案，不直接修改。

只有使用者已经明确授权更新，并且同一缺陷至少有两个真实案例时，才使用 skill-creator 执行：
1. 读取完整 SKILL.md 和必要参考资料。
2. 修改最小必要范围。
3. 删除失效规则，不记录方案演变。
4. 测试新增或修改脚本的成功和失败场景。
5. 运行 quick_validate.py。
6. 对复杂 Skill 做不泄漏预期答案的真实任务前向测试。
7. 更新 docs/CHANGELOG.md。

未经明确授权不得提交、推送、创建 PR 或发布外部变更。
```

## 可选的每周索引

推荐时间：每周五 18:00。

```text
汇总本周 Codex 任务，记录日期、项目、用户目标、工作类型、使用的 Skill、交付物、完成状态、返工原因和未解决问题。

只追加轻量索引，不评价或修改 Skill。
如果现有任务历史可以在月末直接完整检索，则不需要生成独立索引文件。
```

## 调度建议

```text
每周五 18:00：可选的轻量索引
每月最后一天 20:00：只读月度复盘
每月第一天 10:00：更新评估与人工确认
```

不要把“报告”和“自动修改”放在同一个无人工确认的定时任务中。
