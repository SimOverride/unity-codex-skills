# 项目总体文档

## 项目目标

本仓库维护一组可跨 Unity 项目复用的个人 Codex Skill，减少模块规划、功能交付、Blender 资产制作和渲染排障中的重复分析与漏项。

## Skill 体系

### Unity 功能模块规划

负责将粗略需求整理成可实施计划，输出模块目标、非目标、数据所有权、运行时状态、核心实体、修改入口、依赖、事件、随机性、生命周期、MVP 和阻塞问题。

不修改项目，不预设具体领域实现。

### Unity 模块交付

负责在规划明确后检查现有项目、实现功能、处理生命周期与引用、同步当前状态文档，并完成编译、测试、CRLF、差异和 CodeGraph 验证。

不代替前期模块规划，也不承担专项 Blender 或渲染诊断。

### Blender Unity 资产管线

负责静态道具、参数化资产和骨骼动画资产的建模、结构、材质、UV、法线、轴心、拓扑预算、FBX 导出与回读验收。

资产结构以 Unity 中的换色、动画、性能和导入需求为合同。

### Unity 渲染排障

负责把画面问题定位到场景与相机、Renderer 与材质、Shader Pass、模型与导入、多对象交互或目标平台层级，并通过最小隔离实验确定根因。

用户只要求分析时保持只读；明确要求修复后才修改项目。

## 维护原则

1. Skill 只保存模型无法从通用知识稳定推导出的个人流程、边界和检查点。
2. 详细资料按需加载，避免把所有内容写入 `SKILL.md`。
3. 脚本用于确定性检查，不替代真实项目验证。
4. 项目约束留在项目 `AGENTS.md`，不复制进所有 Skill。
5. 每月通过对话复盘发现重复工作流、Skill 漏项和失效规则。
6. 所有更新必须有真实案例证据和验证结果。

## 发布与安装

仓库是 Skill 的版本来源。个人 Codex 目录是安装结果。

推荐流程：

```text
仓库修改
→ 结构与脚本验证
→ Git 提交
→ 复制到个人 Skill 目录
→ 用真实任务验证
→ 将发现反馈到下次仓库更新
```

不要直接在仓库和个人安装目录同时修改同一个 Skill，避免产生两份不同来源。
